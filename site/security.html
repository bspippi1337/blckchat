Privacy & security

Current status: BLCKCHAT is an early prototype. It is not yet a secure, hosted, end-to-end encrypted messenger. Do not use it for sensitive communications.

Public site versus private messages

GitHub Pages serves documentation and public release discovery only. It cannot safely host session state, private chats, access keys or SMS-token redemption logic. Those require a separate HTTPS gateway.

Invitation tokens

The planned flow generates unpredictable 256-bit single-use tokens with a cryptographically secure source, defaults to a ten-minute lifetime, records only a keyed digest server-side and redeems tokens atomically over HTTPS. The web client extracts tokens from URL fragments and immediately clears them from history; logs, analytics and referrers must never contain them.

Possession of an SMS token does not prove identity. SMS can be forwarded or intercepted, so room administrators must have revocation and optionally manual admission approval.

Credentials and encryption

The administrator's GitHub token is only available to the gateway, in protected server-side storage. Guests receive scoped sessions, not GitHub credentials. A private GitHub repository alone is not end-to-end encryption. Audited cryptography, group key rotation and device verification remain future work.

Trust boundaries

Public Pages host → static read-only content. Guest client → HTTPS gateway. Gateway → private GitHub repository. No secret flows from the private gateway into the Pages build.
